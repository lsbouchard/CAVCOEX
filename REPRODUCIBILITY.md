## Measured wall times

Wall times are observations on the platform above, not portable benchmarks.

| Command/campaign | Cache state | Wall time |
|---|---|---:|
| Stable-fluid hard-sphere campaign, 10 states | Existing Numba cache | 32.6 s |
| Baseline fcc reference campaign initialized without defects, 2 states | Existing Numba cache | 16.3 s |
| Independent fcc audit initialized without defects, 8 trajectories | Existing Numba cache | 66.0 s |

The final additional lattice campaign contains 40 trajectories (eight at each
of five sizes). It was expanded during analysis rather than run as a clean
timing benchmark, so no wall-time number is assigned to it. The full
`make reproduce-all` workflow is intentionally
not described as a sub-minute command.  `make pdf` performs only the fast TeX
build from existing generated products.

`make all` now selects `make reproduce`: deterministic calculations and
lattice analysis from the archived trajectories, followed by tests and the
document build. `make reproduce-all` additionally replaces the Monte Carlo
campaigns and should be run in a separate copy when preserving a frozen
release. Make recipes are serialized even when invoked with `-j`, because
several analyses consume products generated by earlier recipes.
BLAS, OpenMP, Numba and NumExpr default to one thread in the Makefile; an
explicit environment or Make variable overrides that default. The dense
hard-sphere cell list rejects allocations over 128 MiB before allocation.

## Continuum diagnostic histories

The full audit bundle's continuum archives include exploratory histories that did not establish
equilibrium phase weights. They are retained as diagnostic evidence, not
pooled into a common-normalization result. The current scientific status is
recorded in `CONTINUUM_SWITCHING_20260929.md` (shared with the lean code release)
and `REAUDIT_SOL_20260929.md` (full publication project).
Continuum simulation generation is opt-in; ordinary document builds do not
replace these archives.
The lean code checkout omits all exploratory continuum raw trajectories,
checkpoints, startup-source copies and detailed diagnostic plots. It retains
the current simulation/analysis code, independent controls, a compact
diagnostic summary with hashes, and all baseline publication inputs. Omitted
failed pilots are not inputs to the publication's quantitative conclusions.

Four earliest diagnostic pilots predate startup source capture:
`continuum_mu16_pilot`, `continuum_mu16_refined`,
`continuum_mu145_refined_fluid`, and `continuum_mu155_soft_fluid`.
Their raw-data hashes remain verifiable, but their recorded source hashes
were not guaranteed to identify the executed bytes: the source was read at
the end, and some runs overlapped edits to the on-disk file. Exact executed
source recovery is unavailable for those four histories. Their original
records are preserved without retrospective relabeling. Later histories
include startup-captured source snapshots whose digests are independently
checked; no early pilot supplies a publication phase-weight result.

To generate a bounded new demonstration from the lean checkout, without
overwriting publication inputs:

```sh
python3 scripts/continuum_replica_exchange.py \
  --tempering hard --sites 32 --mu 14.8 --initialization fluid \
  --equil-sweeps 1000 --production-sweeps 2000 --sample-stride 20 \
  --chunk-sweeps 500 --palm-transfer --seed 2026092999 \
  --output tmp/continuum_demo
python3 scripts/continuum_analyze.py \
  tmp/continuum_demo.npz --block-sweeps 100 --bootstrap 200 \
  --output tmp/continuum_demo_audit.json
```

This intentionally short two-endpoint demonstration does not establish
coexistence or equilibrium phase weights. Direct empty-cavity events may
remain unobserved; the corresponding work is reported as unresolved, not
replaced by an identity-derived value. The frozen multi-node exploratory
histories can instead be reanalysed from the full audit bundle by passing
their raw paths to the same analyzer.
The full project's optional `make continuum-diagnostics` target replays the
final two three-segment lineages and regenerates the compact summary without
running Monte Carlo. It is deliberately separate from `make reproduce`,
whose numerical inputs support the manuscript.

The custom output receives adjacent diagnostic figures and its own execution
metadata. The analyzer verifies raw-data digests, uses common time-block
indices across exchanged replicas, and reports each history separately.
Only physical cavity-path arrays are copied for bootstrap draws; this retains
the same common indices and estimates while avoiding repeated copies of
unused auxiliary replicas. Global inventory summaries include production
quarters as well as halves to expose slow drift.
It checks endpoint product inventories, reduced-Palm marginal identities,
the global hard-node phase inventory, and actual walker transport. An ideal
reservoir is reported only when such a node exists. High move acceptance,
endpoint flips, and agreement with one identity cannot substitute for
independent-start agreement or adequate phase coverage.

Restart segments are linked histories, not new independent replicates. Each
process resets walker labels to replica-slot indices, so separate transport
counts cannot be added to obtain lineage totals. The read-only
`scripts/continuum_lineage_transport.py` reconstructs labels only after
verifying parent raw hashes, executed-source semantics, final-frame cadence,
all checkpoint slots, graph targets and all proposal scales. It joins only
walker identities, not thermodynamic estimates; resulting saved-frame
transport counts still miss any excursions between observations and do not
certify equilibration.

### Separate single-host regenerative tempering

`scripts/continuum_simulated_tempering.py` implements a distinct one-host
extended ensemble with frozen label weights. Its raw schema is
`cavcoex.single_host_regenerative_tempering.v1`, not the product-replica schema.
The graph and initial efficiency weights may be imported from archived
diagnostic histories, but those histories do not supply physical phase odds.
Such graph inputs are in the full audit archive, not the lean code release.
The optional native graph generator, `scripts/continuum_tempering_graph.py`,
instead constructs a graph from explicit scalar settings. Its default is an
unbiased hard-activity path and a designated ideal reservoir. Its
`cavcoex.native_tempering_graph.v1` files contain targets and
initial efficiency weights, not trajectory observations or equilibrium phase
probabilities. Analysis verifies the imported raw file, sidecar, executed
source snapshots, target arrays and initial-weight convention separately.
The explicit-box mode is self-contained in the lean release; no previous
dense history is needed. For a bounded opt-in protocol check:

```sh
python3 -m scripts.continuum_tempering_graph --volume 30.8496 --sites 32 --cap 80 \
  --base-field 16 --cavity-radius-stages 16 --output tmp/native_radius_demo
python3 -m scripts.continuum_simulated_tempering --graph-from tmp/native_radius_demo.npz \
  --output tmp/native_protocol_demo --gibbs-label --calibration-method staged_wang_landau \
  --calibration-steps 500 --production-steps 1000 --chunk-steps 250 --coordinate-stride 10
python3 scripts/continuum_single_walker_analyze.py tmp/native_protocol_demo.npz \
  --bootstrap 200 --output tmp/native_protocol_demo_analysis.json
```

Use new output names: existing archives are not overwritten by default.
This short example checks execution and bookkeeping only; its deliberately
small calibration budget will not meet the stage criteria and is not a
recipe for measuring dense phase probabilities. Explicit native metadata
records every box/graph scalar and executed source; the analyzer independently
reconstructs its targets and initial efficiency weights. An empty input-file
map is permitted only for this declared explicit construction. Graphs derived
from earlier archives retain their required input-file hashes.

The opt-in `--graph-kind compact` construction instead provides soft-pair,
order and number auxiliary paths sharing the same unbiased hard base and
cavity endpoints. It requires explicit box parameters and an FCC reference
size `sites=4*m^3` no larger than the computational cap. The high-order
number restraint targets `sites`; the low-order restraint targets
`volume/1.06448`. Both are auxiliary design choices, removed before the
physical endpoints, not imposed physical occupancies or phase odds. Its
initial efficiency guesses use the explicitly versioned
`soft_cs_number_gaussian_bragg_v1` surrogate with bound constants. In
particular, the surrogate's packing-fraction cutoff of 0.74 is only a
regularization of the guessed partition sum: it does not remove any
configuration or particle-number sector from the sampled targets. The
designated ideal reservoir has activity `log(1/1.06448)` and an exact capped
Poisson number law. Optional radius stages remain unbiased physical targets.
This native graph can be built without any archived failed pilot.

The compact-only `--ordered-hardening-number-strength H` optionally relaxes
the ordered number restraint after the Bragg-preference ramp, with
`0 < H <= 4`. The default `H=4` preserves the original arrays and initial
weights exactly and adds no labels. For smaller H, two fixed-softness,
fixed-order labels change the restraint from 4 through `sqrt(4*H)` to H;
the subsequent hardening uses H, followed by removal through
`H/2, H/4, H/8, H/16, H/40, 0`. The low-order route is unchanged, and every
physical target remains unrestrained. H is an auxiliary efficiency setting,
not a physical parameter or an inferred phase probability. Its value and
resulting arrays are independently reconstructed from the graph metadata.

Independent actual small-system controls compare the engine with capped
continuum partition quadrature, including nonzero order/number umbrellas,
irregular graph degrees, insertion proposals, hard support and the ideal
refresh. Artificially capped controls do not justify uncapped Palm identities.
The small independent control at
`data_raw/controls/single_walker_capped_control_20260929.npz` is retained in
both release profiles, together with its sidecar and only the exact
hash-verified source snapshots it references. Its producer is the independent
test harness, not a run of the simulation driver's main CLI. To inspect it:

```sh
python3 scripts/continuum_single_walker_analyze.py \
  data_raw/controls/single_walker_capped_control_20260929.npz \
  --bootstrap 500 --output tmp/single_walker_control_analysis.json
python3 -m scripts.continuum_tempering_structure \
  data_raw/controls/single_walker_capped_control_20260929.npz \
  --output tmp/single_walker_control_structure.json --minimum-particles 20
```

These are low-particle-number implementation and geometric checks, not
observations of fluid or solid phases.
Additional actual-engine tests cover unequal chemical activities and an
exactly solvable periodic cell with box length equal to the hard diameter.
In the latter, at most one physical host fits and the matched cavity is
empty; a capacity of two is therefore inactive for the physical targets.
This separately checks the unrestricted Palm/Fano identities and cavity
work. It is not a coexistence or contact-derivative experiment.

Use `scripts/continuum_single_walker_analyze.py` for this schema. It records
every fixed-clock dwell and rejection, validates frozen weights and executed
source/input hashes, preserves its own startup source bytes in a
content-addressed snapshot, and divides summed complete-cycle rewards by summed
cycle dwell. Zero-physical-dwell cycles are retained. A cycle starts at the
designated ideal-node heatbath and ends just before the next such event;
leading and terminal incomplete cycles are omitted. The cavity/base partition
ratio additionally removes the known label-weight difference from their
relative dwell. Common whole-cycle resampling preserves the covariance of
these ratios. A resample with no required endpoint visits is left undefined,
not silently discarded. The fixed-clock stopping design yields a random
duration-dependent prefix of complete cycles, so the reported errors are
asymptotic, not an exact finite-sample unbiasedness assertion.
Activity-resolved profiles condition on each label separately; they do not
pool states at different chemical activities. Large incomplete-history
fractions and concentration of endpoint dwell in one completed cycle are
reported explicitly. With no complete cycles, thermodynamic estimates stay
undefined even when a long partial excursion has visited physical labels.
Display-ready basin-probability errors are suppressed when a basin is
unobserved, few cycles contribute to either basin, one cycle dominates dwell,
or incomplete cycles dominate the horizon. Raw empirical errors remain
available as diagnostics. Passing these reporting checks is not an
equilibrium certificate; an exact structural zero is a separate analytic
statement, not something established by observing no events.

Optional conditional-label Gibbs updates are recorded separately from the
lazy neighbor/Palm move. The full-clock observation precedes both updates;
an additional intermediate-label array identifies the post-Gibbs label from
which the neighbor proposal starts. Separate Gibbs counters are required.
Adjacent full-clock labels must not be interpreted as a single neighbor move
when this composition is enabled. Legacy neighbor-only archives remain
readable under their original protocol.

The optional `--vacancy-relocation-probability` (default zero) adds a
fixed-number local move before the clock observation. It chooses one host
particle uniformly and proposes its replacement from the same
residual-configuration vacancy density used in the reverse move, with the
full Metropolis--Hastings ratio. It applies only at same-diameter structured
labels; physical target weights are unchanged. Archives bind the proposal,
scope, timing and probability, with a separate production attempt/accept
counter pair. The strict loader checks those counters against eligible
nonempty observation clocks. These are proposal diagnostics, not additional
observations or evidence of phase equilibration.

Analysis, structural replay and gate outputs use new prefixes: an existing
result or metadata sidecar is preserved, not overwritten. Historical replays
therefore receive versioned output names. Their current execution source
snapshots are distinct from historical records; an unavailable historical
producer is not reconstructed approximately or assigned a new hash.

The optional staged discarded calibration records two distinct histograms:
the pre-hop observation labels paired with number/order features, and the
final labels whose weights were actually decremented. Each stage records
its gain, cumulative counts, clock interval, half-epoch number/order checks,
and final weight vector. The loader independently checks these records and
the actual production cutoff. Flatness and half-epoch stability flags are
label-efficiency diagnostics only, not physical equilibration criteria.
Production weights are frozen even if the finite calibration budget ends
without those diagnostics passing.

The optional `--calibration-label-quota endpoint_priority` allocates desired
label visits as 0.30 to the base, 0.30 to the full cavity, 0.02 to the
designated ideal reservoir, and the remaining 0.38 equally over all other
labels. These are label-sampling allocations, not phase probabilities.
Discarded adaptation adds `gain*quota` to every log weight and subtracts
`gain` at the visited update label. Flatness then uses visits divided by
quota; the minimum actual visit count and correctly paired number/order
half-mean checks are unchanged. Uniform is the default and executes the
historical decrement-only arithmetic. The raw normalized quota, metadata,
outcome and scaled stage counts are bound by the strict loader, including
the periodic gauge interval and numerical clipping bounds. All frozen
conditional physical targets and complete-cycle estimators are unchanged.
For newly quota-declared staged records, the analyzer also reconstructs
every gauge-invariant checkpoint weight increment from its constant gain
and actual label-count differences, including stage resets. A conservative
interval bound must rule out an intervening numerical clamp; otherwise the
record is rejected for insufficient ordered-update evidence, not for an
incorrect physical target. The comparison allows a step-count-dependent
floating-point roundoff envelope. Historical quota-absent records retain
their original validation semantics, and variable-gain one-over-t paths
are explicitly not reconstructed from unweighted aggregate counts.

The optional `--calibration-normalizer-projection nested_physical_radius`
regularizes only staged, discarded calibration. It jointly projects the
physical-path variables `a=b-log(quota)` onto adjacent monotonicity and
exact finite endpoint-span bounds. The proof domain requires a declared
nested hard cavity path at common activity and diameter, no order/number
restraints, a box at least one diameter wide and an inactive physical cap.
The conservative geometric particle bound is
`N_bound=ceil(6*volume/(pi*sigma^3))`; the endpoint span lies between
`max(0,activity+log(volume)-log(N_bound))` and
`log(1+exp(activity)*volume)`. These are necessary normalizer constraints,
not physical phase odds or supplied cavity-work measurements.

The default `none` preserves the original computation. Enabled archives
record the helper's executed bytes, every pre-projection full weight vector
and the projected path values and solver diagnostics. Constant-gain replay
uses the previous POST vector and current PRE vector, then independently
checks simultaneous feasibility and Euclidean-projection KKT optimality.
No off-path weight is changed between the recorded PRE and POST states;
the stage-end common gauge is handled separately. A solver-success flag
alone is insufficient, and projection is never applied during frozen
production. Such efficiency regularization does not certify phase mixing.

Sparse coordinate snapshots are separately aligned to the full-clock trace;
they cannot replace full-clock cycle rewards. This engine has no simultaneous
replica-product covariance diagnostic. Adequate independent regenerated
physical visits, occupancy support, structural checks, and agreement of
independent starts remain necessary before interpreting dense phase weights.
See `SINGLE_WALKER_CONTINUUM_PLAN_20260929.md`. These experimental calculations
are opt-in and do not alter the manuscript's quantitative evidence.

### Product-replica start and support diagnostics

Independent-start comparisons require matching physical activity, volume,
diameter and cavity radius, plus a geometric certificate that the particle
capacity does not truncate the physical ensemble. Basin fractions also
require matching recorded labels. Auxiliary graphs and proposals may differ
and are identified explicitly. The comparison inspects the full recorded
per-replica displacement scales, including physical activity probes, rather
than inferring equal tuning from command-line settings. Early
`--auxiliary-from` histories copied tuned core scales but not probe scales;
these histories still share the stated physical target, but cannot be called
identically tuned at every node. Combined standard errors are reported only
when distinct fresh random histories are documented; they describe
within-history variability, not missing phases or common bias. Boundary
fractions with zero bootstrap variance are never exact equilibrium precision.
The endpoint-number covariance also carries a coarse joint-support check:
below-modal, modal, and above-modal particle counts are cross-tabulated. If
simultaneous number fluctuations are rarely or never observed, an empirical
bootstrap cannot generate the missing tail. Its nominal covariance/standard-
error ratio is then reported only descriptively, not as a calibrated
independence rejection. The counts are correlated observations, not an
effective binomial sample size.

A two-radius run provides direct rare-empty-event sampling, not a resolved
multistage insertion-work measurement. Zero observed support events leave
the work unresolved; zero-support bootstrap draws can also leave its
uncertainty unresolved even when the empirical work is finite. The GNZ
identity is not substituted for the missing support measurement. Alternative
basin thresholds require recomputing every delete-one label from coordinates,
not reinterpreting the stored fixed-threshold deletion statistic. Thinned
probe coordinates use explicit indices into the full diagnostic time series.
Optional pair-overlap observations are validated as integer host-pair counts
and must vanish at every truly hard node. Their auxiliary-node distributions
and production-quarter means diagnose soft-to-hard bottlenecks without
altering the sampled target or claiming equilibration.
Optional auxiliary number umbrellas are recorded by paired
`number_stiffness` and `number_preferred` arrays. Every physical cavity stage
and activity probe must have zero number bias; number-biased auxiliaries are
excluded from the unbiased hard-node inventory and ideal-reservoir detector.
Legacy archives without the arrays mean zero bias only when their execution
settings do not declare the new number umbrella.

The radius-dependent cavity analysis also has deterministic geometry controls:
small-ball counting in translated configurations, open-ball exclusion, the
thin-shell remainder bound, and the host--tracer radius chain factor. These
are independent of the sampler and do not purport to simulate coexistence.

## Release integrity

`pytest.ini` limits default test discovery to `tests/`. Historical executed
test-source snapshots are retained as provenance, not automatically collected
and executed as additional current tests.

`scripts/make_release_manifest.py` hashes every curated source, script, test,
raw-data, processed-data, generated-metadata, figure, and final PDF file. `SHA256SUMS` is
generated only after the final numerical and TeX builds. Run it with
`--check` to verify the frozen state without rewriting the manifest. Missing
required inputs fail verification rather than being silently omitted.

Numerical generators record execution provenance. The packaging helper
`scripts/enrich_metadata_provenance.py` writes a separate
`generated/release_provenance.json`, a current snapshot of distributed source
and input files, leaving execution metadata bytes unchanged. This snapshot does not assert
that any command was executed. Legacy August metadata included top-level
hashes refreshed at packaging time, so those alone must not be interpreted as
proof of the original executed source. The original hard-sphere execution
hashes are also embedded in the raw block records; the prior solid-cavity
source is retained under `data_raw/source_snapshots/` and checked against its
recorded hash.
